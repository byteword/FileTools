# 기존 기능과 일관된 추가 기능 제안

검토일: 2026-09-19.
상태: 최초 제안 기록. 후속 요청으로 빈 폴더 휴지통 정리와 일괄 이름 편집을 구현했다.
현재 동작과 검증은 [기능 문서](file-organization.md)를 참고한다.

후속 결정: 사용자가 다음 마이너 버전용 브랜치와 순차 구현 준비를 요청했다.
선택된 순서는 빈 폴더 정리 → 일괄 이름 편집 → 중복파일 확인 고도화 →
파일 목록 작성 → 조건별 파일 모으기다. 최신 준비 상태는
[1.5.0.0 구현 계획](v1.5.0.0-implementation-plan.md)을 따른다.
아래 추천 순위와 기준 버전은 최초 검토 당시의 기록으로 유지한다.

## 판단 기준

현재 작업 트리의 구현과 문서를 기준으로 검토했다. README의 표시 버전은
`1.4.6.4`이며, 아직 커밋되지 않은 폴더 병합/씌우기 후속 변경도 포함한다.
설치된 앱이나 공개 배포본의 기능 상태를 검증한 문서는 아니다.

FileTools의 중심은 사용자가 고른 파일/폴더의 이름, 폴더 구조, 위치와
중복을 정리하는 작업이다. 추가 기능은 이 흐름의 반복 수고를 줄이고,
기존 이름 계산·충돌 처리·작업 계획을 재사용할 수 있는지를 기준으로 골랐다.

사용빈도와 개발 규모는 코드 검토 및 일반적인 파일 정리 시나리오에 따른
정성적 추정이다. 실제 사용자 이용 통계나 개발 일정 측정값은 아니다.

## 추천 순서

체감 효과, 예상 반복 사용, 기존 기능 재사용과 구현 규모를 함께 고려한 순서다.

| 순위 | 기능 | 예상 사용빈도 | 개발 규모 | 추가되는 가치 |
| --- | --- | --- | --- | --- |
| 1 | 간편 일괄 이름 편집 | 높음 | 중간 | 선택한 묶음에 일회성 치환·문구 추가·연속 번호를 적용 |
| 2 | 작업 조합 프리셋 | 높음, 같은 정리를 반복할 때 특히 유용 | 중간 | 여러 작업의 순서와 옵션을 저장하고 새 대상에 재사용 |
| 3 | 조건별 하위 파일 수집 | 높음, 여러 폴더를 정리할 때 유용 | 중간 | 확장자·이름·크기·날짜 조건으로 작업할 파일을 한 번에 수집 |

| 5 | 빈 폴더 정리 | 중간 | 작음~중간 | 재배치나 중복 삭제 후 남은 빈 구조를 정리 |

### 1. 간편 일괄 이름 편집

자동 교정 외에도 사용자가 정한 규칙대로 여러 파일을 한 번에 바꿀 수 있게 한다.

- 예: `이미지1.jpg`, `이미지2.jpg`, `이미지10.jpg`를 이름의 숫자 순서로
  정렬하고 `자료_001.jpg`, `자료_002.jpg`, `자료_003.jpg`로 변경한다.
- 첫 범위: 문자열 바꾸기, 앞/뒤 문구 추가·제거, 새 이름 형식,
  번호 시작값·증가값·자릿수, 번호 부여 순서, 확장자 유지.
- 이번 선택에 적용하는 규칙과 저장된 전역 교정 규칙을 구분한다.
  문자열/정규식 치환 알고리즘은 기존 구현을 활용하고, 일회성 적용 범위와
  선택 순서 기반 번호 부여를 추가한다.
- 번호를 붙인 최종 이름 전체를 대상으로 충돌을 계산한 뒤 검토·실행한다.
  공용 템플릿의 기존 `Index`는 현재 충돌 번호 등에 쓰이므로,
  사용자 지정 연속 번호의 의미와 혼동하지 않도록 구분해야 한다.

여러 문서, 스캔 이미지, 압축 묶음 등 다양한 파일에 적용되므로 첫 기능으로 추천한다.
확장자별 파일 내용을 읽는 처리 없이도 유용한 범위를 만들 수 있다.

### 2. 작업 조합 프리셋

예를 들어 `이름 자동 교정 → 파일별 폴더 씌우기 → 제목 초성별 재배치`를
하나의 이름으로 저장하고, 다음에 선택한 파일들에 다시 적용한다.

- 첫 범위: 이름 교정, 파일별 씌우기, 단일 파일 폴더 벗기기,
  자동 재배치처럼 현재 대상별 단계로 표현되는 작업 조합.
- 적용할 때 새 대상의 이름과 경로를 다시 계산하고 검토한 뒤 실행한다.
- 작업 종류·순서·옵션을 저장한다. 이전 대상의 확정 파일명이나 원본 절대경로를
  새 대상에 그대로 복제해서는 안 된다.
- 현재 `AddRenameSteps`는 확정된 이름을 `ManualRenameFileName`으로 저장한다.
  따라서 `WorkPlanStep.Clone()`과 JSON 저장만 추가해서는 재사용 가능한
  이름 교정 프리셋이 되지 않는다. 변환 규칙과 확정 결과의 분리가 필요하다.
- ZIP 병합의 소스 묶음, 중복 삭제의 보존/삭제 경로, 즉시 실행되는 선택 묶음
  씌우기·폴더 병합은 그룹 대상 모델을 정의한 뒤 확장한다.

같은 형태의 자료를 반복 정리한다면 1번보다 먼저 구현할 가치도 있다.
자동 재배치 템플릿 저장은 이미 있으므로, 추가 범위는 여러 작업을 묶은 재사용이다.

### 3. 조건별 하위 파일 수집

예를 들어 여러 폴더 아래의 `jpg/png`만 모아서 일괄 이름을 바꾸거나,
지정 날짜 이후의 PDF만 모아서 기존 자동 재배치에 넘긴다.

- 첫 범위: 현재 폴더/하위 포함 선택, 확장자·이름 조건, 크기·수정일 범위,
  제외 경로, 수집 결과 중복 제거.
- 수집은 처리할 파일 목록을 확정하는 단계다. 확정한 파일 목록에 기존 작업을 적용한다.
- 기본 범위를 파일로 한정하면 부모 폴더와 자식 파일을 동시에 이동하는
  문제를 줄일 수 있다. 연결된 폴더는 기본적으로 따라가지 않고,
  읽지 못한 경로와 제외한 경로를 구분해 기록한다.
- 비교 엔진은 이미 폴더를 재귀 확장한다. 추가할 것은 이름 변경·재배치 등에서도
  공통으로 쓸 조건부 수집이며, 기존 재배치 전용 사전 필터와 역할이 다르다.
- 현재 `MainForm.AddPaths`와 `RenamePlanner.CreatePlan`은 전달받은 경로를
  대상으로 처리하므로, 기존 경로 선택을 바꾸지 않는 별도 수집 단계가 적합하다.

### 4. 실행 이력과 되돌리기

실행 단위로 무엇이 어디에서 어디로 바뀌었는지 기록하고, 복구 가능한 작업을
역순으로 되돌린다. 직접 복구하는 빈도보다 대량 정리의 실수 비용을 줄이는 가치가 크다.

- 첫 범위: 같은 볼륨의 개별 파일 이름 변경과 이동.
- 실제 실행 전 의도와 실행 후 성공 여부를 기록하고, 원래 경로·최종 경로·
  파일 식별/변경 상태를 이용해 복구 가능 여부를 판단한다.
- 원래 위치가 다른 파일에 의해 점유되었거나 실행 후 파일이 교체된 경우는
  자동 덮어쓰기 없이 복구 보류로 남긴다.
- 폴더 씌우기·벗기기·병합은 자식별 이동과 생성/삭제한 폴더까지 기록한 뒤
  지원한다. 대상 하나의 시작/종료 경로만으로는 재귀 병합을 복구할 수 없다.
- 압축 병합의 원본 삭제, 휴지통 복원, 다른 볼륨으로 이동한 작업은 각각
  복구 정책을 정한 뒤 지원 범위를 넓힌다.
- 탐색기 실행, 즉시 실행 폴더 작업과 작업 계획 실행이 공통 기록을 남기도록
  실제 파일 작업 계층에 연결해야 한다.

현재 로그 문자열을 역으로 읽어 이동하는 방식으로 구현 범위를 축소하지 않는다.
먼저 구조화된 이력을 확보한 다음 되돌리기를 추가하는 단계적 구현이 적합하다.

### 5. 빈 폴더 정리

선택한 루트 아래에서 실제로 빈 폴더를 찾아 정리한다. 특히 자동 재배치와
중복 파일 삭제가 끝난 뒤 남는 디렉터리 구조에 유용하다.

- 첫 범위: 파일이나 보존해야 할 하위 항목이 없는 폴더를 아래에서 위로 정리.
- 폴더를 비어 있다고 판단할 때 숨김/시스템 파일을 포함한 모든 항목을 확인한다.
  실행 직전에 다시 확인하고, 읽기 실패는 빈 폴더로 취급하지 않는다.
- 선택 루트와 연결된 폴더는 기본 제외하고 휴지통 이동을 기본으로 검토한다.
- 기존 병합/벗기기가 작업 중 비워진 원본을 정리하는 동작과 연결하되,
  독립적인 탐색·정리 기능으로 범위를 명시한다.
- 크기가 0인 파일 삭제는 이 기능에 포함하지 않는다.

## 구현 선택 제안

하나만 고르면 **간편 일괄 이름 편집**을 추천한다. 우선 선택한 파일에만 적용하는
규칙, 번호 부여, 확장자 유지와 최종 이름 충돌 검토로 범위를 잡는다.
그 변환 정의를 재사용 가능하게 만들면 **작업 조합 프리셋**으로 확장하기 좋다.

폴더별 정리 작업을 반복하는 사용이 더 많다면 작업 프리셋과 조건별 수집을
앞당길 수 있다. 실행 이력은 실제 파일 작업 계층의 변경이 필요한 기반 작업으로
따로 규모를 잡는다.

기존 비교 기능을 개선할 때는 이름·시각에 관계없이 전체 내용으로 찾는
중복 검색 설정과 대량 입력의 성능을 함께 살펴볼 만하다. 현재 비교 루프는
모든 파일 쌍을 비교하고 기본 옵션에 이름/수정 시각 비교가 포함된다.
중복 삭제 자체는 이미 구현되어 있으므로 별도 신규 기능으로 중복 제안하지 않는다.

## 외부 사례 참고

- [Microsoft PowerRename 공식 문서](https://learn.microsoft.com/en-us/windows/powertoys/powerrename)는
  일괄 치환과 번호 시작값·증가값·자릿수 지정, 이름 변경 취소를 설명한다.
- [Double Commander Multi-Rename 공식 문서](https://doublecmd.github.io/doc/en/multirename.html)는

두 자료는 기능 패턴의 참고 사례이며 FileTools 이용자의 실제 사용빈도를 입증하는 자료는 아니다.

## 검토 범위와 문서 변경

코드와 문서의 정적 검토로 제안을 작성했다. 실행 코드를 수정하지 않았으며
이 검토에서 빌드, 파일 작업 실행, 설치 확인은 수행하지 않았다.
문서만 추가·연결했고 버전과 릴리스 노트는 변경하지 않았다.
