# 폴더 벗기기 명령 중복 표시 검토

검토/구현일: 2026-09-19. **탐색기 네이티브 메뉴에 구현하고 조건표와 실제 실행 결과를 교차 검증했다.**

## 결론

선택 폴더 전체를 분석한 조건표로 명령 후보를 만든 뒤, 작업 대상·출력 이름·
충돌 처리까지 같은 명령은 대표 하나만 남긴다.
모든 선택 폴더가 같은 이름의 단일 파일 폴더라면 이름 선택 명령들은 실제로
동일하다. 기본 충돌 정책에서는 전체 내용 벗기기까지 묶어 4개를 1개로 줄일 수 있다.

아래는 구현 규칙을 설명하는 그림이다. 설치된 탐색기의 화면 캡처는 아니다.

![탐색기 벗기기 메뉴 최소화 규칙](images/unwrap-menu-dedup-current.png)

## 실행 코드와 대조한 사항

- 기존 메뉴는 명령마다 폴더를 다시 읽고 적용 대상이 하나라도 있으면 표시했다.
  이제 `AnalyzeSelection`이 선택 상태를 한 번 분류하고 `UnwrapMenuPolicy.h`의
  조건표가 활성 명령 중 동등한 결과를 합친다. 명령 ID와 기존 설정 키는 유지한다.
- `FolderStructureNameTemplates.ResolveUnwrappedFileName`은 폴더명과 파일 stem이
  대소문자를 무시하고 같으면 이름 모드나 사용자 템플릿과 관계없이 원래 파일명을
  반환한다. 따라서 이름 일치 선택에서 세 이름 명령의 결과가 동일하다.
- 탐색기 실행의 `Program.FilterContextCommandPaths`는 같은 이름 명령을 일치
  폴더에, 접두어 명령을 불일치 폴더에만 적용한다. 파일명/폴더명 명령은 두 종류
  모두에 적용한다. 혼합 선택에서는 적용 대상 집합도 비교해야 한다.
- 전체 내용 벗기기는 충돌 시 항상 건너뛴다. 단일 파일 벗기기는
  `FolderStructureConflictPolicy`를 따르며 기본값은 `Skip`이다. `AutoNumber`이면
  두 방식은 충돌 상황에서 동등하지 않다.
- 앱의 셸 등록 동기화는 `FolderUnwrapCollisionPolicy`에 정규화한 충돌 정책도
  전달한다. `Ask`/`MergeIntoExisting`은 실행과 동일하게 `Skip`으로 정규화한다.
  기존 설치처럼 값이 없거나 유효하지 않으면 전체 내용 명령을 별도로 남긴다.
  저장된 정책은 다음 설정 저장/메뉴 등록 동기화에서 전달된다.
- 앱의 `SetUnwrapItemsEnabled`는 폴더 선택이면 변형들을 함께 활성화한다.
  또한 앱 플랜은 전체 내용 벗기기 후 부모 폴더, 단일 파일 벗기기 후 파일을
  후속 입력으로 예측한다. 탐색기에서 동일한 파일 이동 결과가 나와도 앱의
  후속 플랜 의미까지 같다고 볼 수 없다.

## 선택 상태와 구현 조건표

- **S:** 파일 1개, 하위 폴더 없음, 폴더명과 확장자를 제외한 파일명 일치.
- **D:** 파일 1개, 하위 폴더 없음, 이름 불일치.
- **M:** 그 밖의 비어 있지 않은 폴더. 여러 파일 또는 하위 폴더가 있음.
- **E:** 빈 폴더. **U:** 읽기 실패, 불완전한 열거 등 판정 불가.

아래 표는 **탐색기에서 상세 분석이 완료된 경우**, 모든 관련 메뉴 활성화, 충돌 정책 `Skip`, 정상 판정된
일반 폴더 선택 기준이다. 폴더 집합 이름은 짧게 표시했다.

| 선택 조합 | 남길 벗기기 명령 | 개수 | 중복/차이 근거 |
| --- | --- | ---: | --- |
| S만 | 같은 이름 단일 파일 | 1 | 폴더명·파일명·전체 내용과 같은 이동 |
| D만 | 파일명 / 폴더명 / 폴더명-파일명 | 3 | 전체 내용은 파일명 유지와 동등 |
| S + D | 같은 이름 단일 파일 / 파일명 / 폴더명 / 폴더명-파일명 | 4 | 같은 이름은 S만, 접두어는 D만 처리. 전체 내용만 파일명과 동등 |
| S + M | 같은 이름 단일 파일 / 전체 내용 | 2 | 이름 변형은 모두 S만 처리. 전체 내용은 M도 처리 |
| D + M | 파일명 / 폴더명 / 폴더명-파일명 / 전체 내용 | 4 | 전체 내용만 M까지 처리 |
| S + D + M | 같은 이름 단일 파일 / 파일명 / 폴더명 / 폴더명-파일명 / 전체 내용 | 5 | 적용 범위 또는 결과가 달라 모두 필요 |
| M만 | 전체 내용 | 1 | 단일 파일 전용 명령은 적용 대상 없음 |
| E만 | 없음 | 0 | 현재 전체 내용 벗기기도 빈 폴더는 삭제하지 않음 |
| 파일 포함 혼합 선택 | 없음 | 0 | 현재 탐색기의 폴더 전용 조건 유지 |

E가 섞이면 실제 이동 대상이 없는 폴더로 취급한다. U가 있으면 동등성을
단정하지 말고 중복 제거를 보수적으로 제한한다. `FindNextFileW` 종료가 정상인지
확인하지 않은 채 부분 열거 결과를 S/D로 확정하지 않도록 해야 한다.

`AutoNumber` 설정에서는 위 표의 S만, D만, S+D에 전체 내용 명령이 하나 더
남을 수 있다. 현재 충돌이 없더라도 실행 전 상태가 바뀔 수 있으므로 **충돌
정책이 다른 명령을 순간적인 대상 파일 부재만 보고 합치지는 않는다.**

## 표시 결정 순서

1. 선택된 폴더별 상태를 한 번 분석해 S/D/M/E/U를 만든다.
   파일 내용은 읽지 않는다. 여러 메뉴 항목이 같은 폴더를 반복 열거하는 비용도 줄인다.
2. 사용자 설정에서 켜진 명령만 후보에 넣고, 실제 처리할 대상이 없는 후보를 뺀다.
3. 후보별 적용 대상 집합, 출력 이름 규칙, 충돌 정책으로 동등성을 비교한다.
   원본은 두 구현 모두 비었을 때만 지운다. 탐색기의 이름 변형은 명시적인
   이름 모드를 사용하며, 사용자 불일치 템플릿도 S의 이름 유지 규칙을 바꾸지 않는다.
4. 동등한 후보는 같은 이름 전용 → 파일명 유지 → 폴더명 사용 → 접두어 → 전체
   내용 순으로 대표를 선택한다. **꺼진 명령을 대표로 삼아 켜진 명령까지 숨기지 않는다.**
5. 클릭 직전 선택 상태를 재검증하고, 실행 시에도 기존 대상 필터를 유지한다.
   분석 결과의 재사용 범위는 해당 메뉴/선택 수명으로 제한한다.

셸의 내용 스냅샷은 실행 권한이나 실행 대상 목록으로 쓰지 않는다. 클릭하면 현재
선택 종류/활성 설정을 확인하고 앱의 `FilterContextCommandPaths`와 실행기가
현재 폴더 상태를 다시 확인한다.

## 메뉴 응답 시간 제한

- `1.4.7.1` 수정: `IExplorerCommand.GetState`의 빠른 호출(`fOkToBeSlow=FALSE`)은
  준비된 상세 스냅샷을 반환하거나 셸 선택의 개수/집계 속성과 설정으로 계산한
  보수적 활성/숨김 상태를 `S_OK`로 반환한다. 후속 느린 호출이 없어도 사용할 수 있다.
  직접적인 파일시스템 읽기, 경로 추출, 폴더 열거, 분석 잠금 대기는 하지 않는다.
  셸의 `GetAttributes` 호출은 사용하며 공급자 자체의 응답 시간까지 보장하지는 않는다.
  설정은 명령 열거자 생성 시 한 번 읽는다.
- 느린 호출이 없는 호스트에서는 상세 중복 제거가 생략되어 명령이 더 많이 남을 수 있다.
  이름/내용 판정이 없어도 메뉴 전체를 비활성으로 만들지 않는다. 실제 실행 조건은
  클릭 후 다시 검사한다. [비활성화 진단](context-menu-disabled-diagnosis-2026-09-19.md) 참고.
- 형제 명령은 열거자에 속한 하나의 캐시를 공유한다. 같은 선택은 한 번 분석하고,
  새 메뉴 열거자는 새 캐시를 만든다. 경로가 같은 선택 객체도 느린 호출에서 재사용한다.
- 느린 검사에서는 경로별 속성을 한 번 읽는다. 폴더 내용은 두 번째 파일 또는 첫
  하위 폴더에서 열거를 끝낸다. 파일 내용을 읽거나 폴더 안으로 재귀 진입하지 않는다.
- 디렉터리당 최대 8회 열거 처리, 메뉴당 속성 읽기 256개/폴더 열기 128개로 제한한다.
  파일 혼합 선택, 벗기기 메뉴가 모두 꺼진 경우, 이미 U가 확인된 경우는 내용 검사를 생략한다.
- 검사 시작 후 50ms가 지나면 다음 읽기를 중단하고 U로 처리한다. 이는 **읽기 사이의
  중단 기준**이며, 진행 중인 Windows I/O 한 번을 취소하거나 전체 메뉴 시간을 50ms로
  보장하는 제한은 아니다. 경로를 가져오는 셸 호출도 느린 단계에서 실행된다.
- UNC/네트워크 드라이브는 파일 속성/내용을 읽지 않는다. reparse point, 읽기 오류,
  시간/개수 제한은 U로 처리해 사용 가능한 명령을 과하게 숨기지 않는다. 따라서 이런
  선택에서는 메뉴 수가 더 많을 수 있으며, 실행 시 앱의 현재 상태 검증을 따른다.
- 단일 파일/빈 폴더는 정상 열거 종료를 확인한 경우에만 확정한다. 파일 1개를 읽은 뒤
  오류가 난 경우를 단일 파일 폴더로 오인하지 않는다.

## 앱 적용 경계

이번 적용 대상은 탐색기 네이티브 메뉴다. 앱의 플랜 메뉴와 정적 레지스트리
fallback에는 이 중복 제거를 적용하지 않았다. 앱에서 재사용하려면 이미 쌓인
플랜의 예상 입력과 후속 출력 종류까지 비교해야 한다. 특히 전체 내용 벗기기는
단일 파일 변형과 단순 통합하지 않는다.
앱 기본 벗기기 항목도 현재 설정을 실제 동작으로 해석한 뒤 동등한 명령이 있을
때 대표로 연결할 수 있으나, 탐색기의 접두어 대상 필터와 앱의 대상 추가 방식
차이를 먼저 명시적으로 맞출 필요가 있다.

## 검증 결과와 재실행

- `scripts/test_unwrap_menu.ps1`: 실제 셸 구현을 포함한 C++ 검증을 빌드/실행하고,
  생성한 조건표 CSV를 C# 실행 결과와 대조한다. VS C++ 워크로드와 .NET 8이 필요하다.
- 네이티브 **600개 검사 통과**: 조건표, 모든 활성 명령 조합, 오류/정상 종료 구분, 조기 종료, 파일 혼합,
  빈 폴더, 네트워크 fallback, 비활성 명령, 대량 선택, COM 캐시와 빠른 호출을 검증한다.
- C#: 네이티브 **1,024개 조건 조합**을 실제 컨텍스트 명령 **960회 실행** 결과와 비교했다.
  숨긴 명령마다 같은 디렉터리/파일 내용 결과를 만드는 표시 명령이 존재하는지,
  표시한 명령끼리는 충돌 상황을 포함해 다른 결과가 가능한지 확인했다.
- 이름 일치/불일치/다중 내용/빈 폴더, Skip/AutoNumber, 기존 충돌 유무, 대소문자 차이,
  확장자 없음, 사용자 불일치 템플릿을 포함한다. 파일 추가/삭제 후 실행 재검증도 통과했다.
- 파일 1,000개 폴더: 속성 읽기 1회, 폴더 열기 1회, 열거 처리 4회(`.`/`..` 포함)로 종료.
  빠른 최초 호출은 분석 0회, 형제 명령 전체가 선택 분석 1회를 공유했다.
- 실제 파일 작업 교차 검증 및 Release 전체 회귀 테스트/솔루션 빌드 통과.
  설치된 Explorer에서의 DLL 교체, 실제 메뉴 표시 지연 측정, MSI 설치 확인은 남아 있다.
