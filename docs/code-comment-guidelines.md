# 코드 주석 가이드 (기본 규칙)

작성자: FileTools 개발 요청 반영
일시: 2026-06-10

앞으로 변경/신규 코드 작업 시 기본적으로 다음 규칙으로 주석을 붙인다.

1. 멤버 변수/필드
   - OS 의존성, 경로 비교 정책, 기본값 조합, 캐시/상태 보관 변수는 한 줄 설명 주석을 기본으로 둔다.

2. 함수
   - public/internal API 및 핵심 private 로직 진입점에는 `summary` 주석을 붙인다.
   - 단순 getters/setters 정도는 과도한 중복 설명은 생략한다.

3. 블록 주석
   - 10줄 이상으로 읽기 어렵거나 분기/루프의 의도가 분명하지 않을 때만 블록 단위로 추가한다.
   - "어떤 조건에서 여기로 들어오고, 어떤 결과를 만든 뒤 빠져나가는지"를 한두 문장으로 설명한다.
   - 기존 코드에서 그대로 가져온 긴 조건식/유니언-파인드/파일 이동 루프처럼 오해 소지가 큰 부분에 집중한다.

4. 기본 정렬 우선순위
   - 코드 변경 시 `동작 설명 > 예외 처리 > 성능/안전성` 순서로 주석을 배치한다.
   - 한국어로 작성하되, UI 문자열(`Localizer`)과 충돌하지 않도록 코멘트는 코드 외 텍스트로만 둔다.

5. 앞으로 적용 범위
   - 이번 반영에서는 운영(Execute), 이름변경/병합/비교/패턴/플러그인/스토어 핵심 파일과 쉘 확장(`src/FileTools.ShellExt/FileToolsShellExt.cpp`)에 우선 적용한다.
   - 이후 새 기능 추가 시 같은 패턴으로 주석을 기본 적용한다.
