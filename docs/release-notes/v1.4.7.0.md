# FileTools v1.4.7.0 — Test build

Local test build following v1.4.6.4. No GitHub release or version tag is created by this packaging task.

## Highlights

- Locked files no longer stop sibling items during unwrapping or content merging;
  partial successes remain counted, and dependent plan steps stop for retry.
- Folder merge combines folder contents recursively; wrapping places the entire
  file/folder selection in one new folder. Per-file wrapping stays separate.
- Collision handling offers numbering (default) or skipping, without overwrites.
- Explorer/menu selection rules and the final-name dialogs use the same meaning.
- Equivalent Explorer unwrap actions share one visible command, with collision
  policy and enabled-action fallbacks preserved. Folder checks are shared and bounded;
  the fast menu callback performs no filesystem analysis.
- See [folder operations](../folder-operations.md) for current Korean dialog images.

## Support Scope

- Windows support is unchanged. Existing command/setting identifiers remain compatible.

## Development verification — 2026-09-19

- Release regression tests passed **157/157**, including real Windows file locks,

- Visual Studio 18 MSBuild `FileTools.sln /p:Configuration=Release /p:Platform=x64`
  completed successfully, including the native ShellExt.
