# FileTools v1.4.7.1 — Explorer menu hotfix

Fixes the 1.4.7.0 regression where every Explorer subcommand could remain disabled
until a slow GetState callback populated the shared cache.

- Repeated fast-only callbacks now return S_OK with usable enabled/hidden states.
- Disabled settings and basic folder/file/count eligibility remain respected.
- No directory enumeration or analysis-lock waiting occurs in the fast fallback.
- Detailed unwrap deduplication still applies after slow analysis. Hosts that never
  request that analysis may display extra commands instead of an unusable menu.
- Current selection and settings are revalidated when invoking a command.
- Version is major.minor.patch.build; this maintenance build changes 1.4.7.0 to 1.4.7.1.

Validation: native fast-only/cache tests, native/managed execution contract tests,
Release managed regression tests, and direct COM probing of the built DLL.
Live Explorer installation is a separate manual verification step.

Results on 2026-09-19: 157 managed tests and 652 native checks passed; the 1,024
policy combinations were cross-checked against 960 actual executions. Direct DLL
probing with repeated FALSE callbacks returned 0 pending/disabled commands
(10 enabled, 4 hidden for the single-folder fixture); detailed analysis returned
6 enabled/8 hidden. The previous DLL returned 14 pending/disabled commands.

The signed test installer was built with `build_msi.ps1 -Version 1.4.7.1` and copied
to `artifacts/test-installers/1.4.7.1/`. App, ShellExt and setup report 1.4.7.1.
Four artifact checksums and signer presence passed; the temporary self-signed
certificate remains untrusted locally (`UnknownError`).

The fix is also merged into codex/1.5.0.0 while retaining its 1.5.0.0 metadata.
