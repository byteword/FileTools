# 1.4.7.0 탐색기 하위 메뉴 비활성화 진단

## 확인한 범위

사용자 증상은 Windows 탐색기의 FileTools 하위 메뉴 전체 비활성화다.
앱 내부 메뉴 문제는 아니다. 실행 코드나 설치 등록을 변경하지 않고 진단했다.

- 설치 등록 DLL: `%APPDATA%\FileTools\FileTools.ShellExt.dll`.
- 실제 DLL 버전: `1.4.7.0`; 배포 빌드 DLL과 SHA-256 일치:
  `CEDF3E6FB8D4CDD93A00545A207245A04F9D3F0A34B87C1CBF30F7BE8CD76F07`.
- 메뉴 활성화 설정 12개는 모두 `1`; 충돌 정책은 Skip (`0`).
- 별도 진단 프로세스에서 설치 DLL의 COM 클래스 팩터리와 하위 명령 열거자를
  직접 호출했다. 검증용 `Same/Same.txt`를 선택 대상으로 전달했으며 Invoke는 호출하지 않았다.

## 재현 결과

| 호출 | 대기 반환 | 활성 | 숨김 | 비활성 상태값 |
| --- | ---: | ---: | ---: | ---: |
| 첫 빠른 호출, FALSE | 14 | 0 | 0 | 14 |
| 두 번째 빠른 호출, FALSE | 14 | 0 | 0 | 14 |
| 느린 호출을 명시적으로 제공, TRUE | 0 | 6 | 8 | 0 |
| 이후 빠른 호출, FALSE | 0 | 6 | 8 | 0 |

## 원인과 증거의 한계

`MenuSelectionCache.GetState`는 상태를 ECS_DISABLED로 초기화한다. 새 캐시의
빠른 호출은 모든 명령에서 E_PENDING을 반환하며, 분석은 TRUE 호출에서만 시작한다.
자체 예약이나 다른 초기화 경로가 없다. 따라서 후속 느린 호출이 없거나 같은
캐시에 도달하지 않으면, 단순한 앱 열기 명령까지 비활성 대기 상태가 지속된다.

이는 사용자 증상을 설명하는 직접적인 실패 경로다. **실제 Explorer 프로세스의
콜백 순서는 추적하지 않았으므로**, 탐색기가 TRUE를 생략하는지, 다른 명령 객체나
선택 객체로 재호출하는지까지는 아직 확정하지 않았다. 설치 DLL과 설정 문제보다는
이번 지연 초기화 설계가 가장 유력하다.

[Microsoft GetState 문서](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iexplorercommand-getstate)는
빠른 호출에서 무거운 처리가 필요하면 E_PENDING을 반환하도록 설명한다.
문서의 처리 방식만 보고 실제 하위 메뉴에서 후속 호출/캐시 재사용이 정상인지
설치 검증 없이 전제한 것이 문제였다.

기존 네이티브 테스트도 FALSE 다음 TRUE를 직접 호출한 뒤 형제 명령을 검사했다.
조건표/파일 결과 검증은 통과했지만, TRUE가 오지 않는 표시 경로의 사용 가능성은
검증하지 못했다. 이전 테스트 통과 보고가 설치된 탐색기 호환성 검증을 의미하지 않는다.

## 수정 방향

- 하위 메뉴 전체의 사용 가능성을 후속 TRUE 호출 하나에 의존시키지 않는다.
- 빠른 경로에서 캐시가 없으면, 설정과 가벼운 선택 정보로 보수적인 활성/숨김
  상태를 성공 반환한다. 특히 앱 열기 같은 내용 분석 불필요 명령은 별도 처리한다.
- 상세 중복 제거용 분석은 메뉴 지연 제한과 함께 분리하고, 결과가 없더라도
  실행 가능한 명령을 비활성 상태로 고정하지 않는다. 임시 중복 표시를 허용한다.
- 반복 FALSE만 들어오는 경우, 선택 객체 변경, 새 열거자, 실제 Explorer의
  하위 메뉴 표시를 회귀 검증한다. 단위 테스트의 TRUE 강제 호출로 대체하지 않는다.

## 1.4.7.1 수정

후속 작업에서 master의 빠른 경로를 수정했다. 준비된 캐시가 없거나 분석 잠금이
사용 중이면 설정과 셸 선택의 개수/집계 속성으로 활성/숨김을 성공 반환한다.
폴더 내용은 열거하지 않는다. ZIP의 폴더 속성은 파일 스트림 속성과 함께 판별한다.
느린 호출이 오지 않는 호스트에서는 상세 중복 제거 대신 보수적 메뉴가 유지된다.
설치된 DLL을 자동 교체하거나 Explorer를 재시작하지는 않는다.
